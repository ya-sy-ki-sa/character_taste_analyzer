## 実装前の結論

キャラクター登録から分析確認、嗜好プロファイル再構築、プロフィール表示、条件付き生成までのアルファ版の縦断導線は成立しています。型検査、単体テスト、DDL・JSON Schema 検査、ビルドも成功し、分離したオフライン環境では主要スモークシナリオを完走しました。

ただし、現時点をそのまま一般公開可能な状態とは判定しません。特に次の4点は、機能追加より先に対処すべきです。

1. 過去 Workflow が再分析後の状態を上書きできるなど、非同期処理に世代フェンスがない。
2. 根拠の出典・入力箇所が実データと一致せず、「原文から追跡」という表示を保証できない。
3. アクセスキーの初回表示・ローテーション画面を閉じると、利用者が復旧できなくなる場合がある。
4. 設定画面の「モデル知識や外部検索を分析根拠にしない」という説明が、現在の実装と反対になっている。

また、同一作品・同一キャラクターを別登録すると毎回別 ID になるため、設計上の「作品・キャラクターの偏り補正」は登録をまたいで効きません。これは分析品質の中核に関わるため、公開前の仕様決定が必要です。

## 優先度の定義

| 優先度 | 意味 |
|---|---|
| P0 | 公開前に解消する。データ誤更新、利用不能、または利用者への重要な説明不一致につながる。 |
| P1 | アルファの信頼性・分析品質を大きく損なう。P0 の直後に解消する。 |
| P2 | ベータまでに改善する。保守性、性能、操作性、運用性を高める。 |
| P3 | 将来拡張。現状の規模では許容できるが、成長時に必要になる。 |

「優先度」は変更規模ではなく、未修正のまま利用されたときの影響で決めています。

### E2E から分かったこと

通常の `npm run test:e2e` は4件すべて失敗しました。既に 5173 番ポートで動いていた通常開発サーバーを `reuseExistingServer: true` で再利用し、E2E 用のオフライン設定ではなく Turnstile 有効設定へ接続したためです。

一時ポートと専用オフライン設定に分離すると4件中2件が成功し、残る2件は次のテストコード側の不安定要因でした。

- `/作品名/` のラベル検索が2要素に一致する。
- セキュリティテストが Origin を `http://localhost:5173` に固定している。

したがって「4件失敗」はプロダクト機能が4件壊れたという意味ではありません。一方で、E2E が実行環境によって別構成へ接続すること自体は、CI 導入前に直すべき問題です。
