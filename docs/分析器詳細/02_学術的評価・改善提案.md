# 学術的評価・改善提案

## 1. 総合判定

### 1.1 現時点で何として良いか

現行システムは、**利用者が自分のキャラクター嗜好を言語化し、根拠とともに振り返る探索的支援ツール**としては、よい基礎設計を持つ。特に次の判断は妥当である。

- 「好き」を、人物好意、同一化、共感、興味、憧れ、親近感、価値支持などに分ける
- キャラクターの特徴と、その特徴に対する利用者の反応を分ける
- 人物への好意、悪役としての魅力、現実での道徳的支持を分ける
- 利用者入力、公開情報、モデル知識の由来を分け、根拠を追跡する
- LLM出力をそのまま確定せず、理解確認と嗜好確認を置く
- 同じキャラクター・作品の反復登録を、そのまま独立票として数えない
- 登録内容から現実の人格、病理、危険性を推測しない

### 1.2 現時点で何とは呼べないか

一方、現行システムを次のように説明するための検証はない。

- 心理診断、性格診断、臨床的評価
- 妥当性・信頼性が確認された心理尺度
- 「本当に好きである確率」や「分析が正しい確率」の測定
- 一般人口との比較、偏差値、標準得点
- キャラクター嗜好から利用者の人格を推定するモデル
- どの特徴が好みを引き起こしたかを示す因果分析

したがって、総合判定は次のとおりである。

> **探索的な個人内嗜好整理器としては有望。学術的に妥当化された測定器としては未完成。**

この区別は単なる言葉遣いではない。心理測定では、測りたい概念の内容が十分に含まれ、利用者に理解可能であることをまず確認し、その後に構造、信頼性、他の測定との関係などを検証する。COSMINの合意形成研究も、内容妥当性を測定特性の中で特に重要なものと位置づけ、関連性・網羅性・理解可能性を評価対象としている（[COSMIN content validity Delphi study](https://pmc.ncbi.nlm.nih.gov/articles/PMC5891557/)）。現行94属性・44反応経路は有用な仮説集合だが、この手続きをまだ経ていない。

COSMINは本来、患者報告アウトカム尺度を主対象とする枠組みである。本レビューでは内容妥当性を確認する一般的な手順の参考として用いており、COSMINへの適合や認証を主張するものではない。

| キャラクター理解と利用者反応の分離 | 良い | 2段階分析と別schema・別確認画面を採用 |

| 「確信度」の校正 | 不適切な表示 | 現行値は根拠寄与と多様性の合成値で、正答確率ではないがUIで百分率表示 |

## 3. 学術的に評価できる長所

### 3.1 「好き」を単一得点に潰していない

同一化は単なる好感や類似ではない。近年のキャラクター同一化尺度も、融合、視点取得、理解、感情的関与という複数要素を検証し、因子構造、信頼性、妥当性、測定不変性を段階的に確認している（[12項目キャラクター同一化尺度](https://link.springer.com/article/10.1007/s12144-024-06191-2)）。現行システムが `person_liking`、`actual_similarity`、`self_projection`、`wishful_identification`、`narrative_identification`を分けたことは、この概念上の混同を避ける方向としてよい。

また、類似性と同一化のメタ分析では39研究、50効果、延べ11,077人を統合した効果は小さく、心理的類似の方が客観的・人口統計的類似より大きい傾向だった（[audience–character similarity meta-analysis](https://research.cuhk.edu.hk/en/publications/the-effect-of-audiencecharacter-similarity-on-identification-with-2/)）。このため「似ているから好き」と一律に逆算せず、実感された類似、投影、憧れ、補完を別経路にした設計は妥当である。

### 3.2 キャラクター像と利用者の嗜好を分けている

キャラクターに `personality.cold` があることと、利用者がその冷淡さを好むことは別である。現行はstage 1でキャラクター理解、stage 2で嗜好assertionを作り、別々に確認する。これは「対象の属性」と「利用者による対象の解釈」と「反応」を混同しにくい。

同様に、既成（カスタム）をbaseとtargetに分けるため、原作の基本像と利用者が加えた差分も区別できる。これはファン解釈・二次的設定を公開設定のように扱わないためのよい境界である。

### 3.3 複雑な道徳反応を扱える

`moral_support`、`fascination_with_transgression`、`love_to_hate`、`desire_no_redemption`と、別の価値orientation・stanceを持つため、「悪役が好き」を善悪の判断へ短絡しない。フィクションへの興味、人物好意、応援、道徳的支持、逸脱の鑑賞を別に記録できることは、悪役・アンチヒーローを含む分析に重要である。

さらに、promptが現実の人格、病理、危険性を推測しないよう制限している。このシステムの入力だけでは、そのような推定に必要な代表的・標準化されたデータがないため、適切な安全境界である。

### 3.4 根拠の由来と人間確認を保存する

入力欄のJSON Pointer、source fragment、引用位置、検証状態、明示性を保存しており、後から「どの記述から候補が出たか」を調べられる。LLMをアノテータとして使う研究では、性能がタスク・データセットに依存し、新しいタスクごとに人手検証集合を作る必要性が指摘されている（[ICWSMのhuman-in-the-loop annotation研究](https://ojs.aaai.org/index.php/ICWSM/article/view/35883)）。現行の確認画面とprovenanceは、その検証を実施できる土台になる。

ただし、`verified_quote`は「文字列の位置と出典が確認できた」という意味であり、記述自体が正しい、解釈が妥当、属性分類が正しいことまでは意味しない。この区別はUIにも明示すべきである。

### 3.5 重複を抑える集計方針

同一Entry内は最大値、同一identity内は割引結合、同一work内も割引結合し、作品をまたいだ独立結合を行う。これは、同じキャラクターを細かく何度も登録するだけで一般的嗜好と誤認するのを抑える。単純件数よりよい探索的ヒューリスティックである。

ただし割引率 `0.25`、`0.5`、安定閾値 `0.65`、identity数3、work数2には、現時点でデータに基づく推定・妥当化はない。「3キャラクター・2作品で科学的に安定した」とは解釈できない。

## 4. 重要な問題点

### 4.1 P0: 確認後データの整合性

#### 問題A: 理解のsummaryが修正後に再計算されない

理解確認でassertionを編集・削除しても、snapshotの `summary_json` はそのままである。次段の嗜好分析には、修正済みassertionと、修正前の可能性があるsummaryの両方が渡る。その結果、利用者が否定した理解がsummary経由で嗜好候補へ残り得る。

改善:

1. 確認確定時に、現存するassertionとcustomization deltaからsummaryを決定論的に再構築する。
2. あるいは嗜好promptから自由文summaryを外し、確認済み構造化レコードだけを正本にする。
3. 「削除したassertionの内容が次段promptに含まれない」結合テストを追加する。

#### 問題B: 理解assertionの意味を変えても属性mappingが残る

`update_assertion` はraw labelや本文を編集しても、以前の `attribute_definition_id` を維持する。たとえば「冷淡」を「思いやりがある」へ書き換えても、内部keyが冷淡のままになる可能性がある。追加assertionは未マッピングで、プロフィールに反映されない。

改善:

1. 意味に関わる編集時はmappingを解除し、利用者に統制属性を再選択させる。
2. 94属性の検索・選択UIを追加し、「その他」は明示的に未集計と表示する。
3. 表示名、本文、mappingの不整合を検出するテストを追加する。

### 4.2 P0: 人間確認が十分な訂正手段になっていない

理解候補は追加・編集・削除できるが、嗜好候補と価値スタンスは削除のみで、誤った属性、polarity、反応経路、strength、文脈を直接修正できない。正しい候補が欠落した場合の追加もできない。これはhuman-in-the-loopというより、候補の拒否だけが可能な仕組みである。

さらに、LLMは候補を最低1件出すよう要求され、0件なら `PREFERENCE_ANALYSIS_EMPTY` で失敗する。好きな理由が未入力でも推測を要求し、UIは `person_liking` を初期選択するため、利用者が積極的に外さない限り仮説が生成される。分析対象が不明確な場合の正解は「分からない／十分な根拠なし」であることも多く、非空制約は偽陽性を増やす。

改善:

- 嗜好候補に追加、編集、polarity変更、反応経路変更、文脈変更を実装する。
- 「この登録からは嗜好を特定できない」を正常終了として許容する。
- 初期状態は反応経路0件とし、利用者に明示選択を促す。簡易モードで既定値を使うなら「仮選択」と明示する。
- `inferred` を一括確認したときも、根拠由来と利用者確認を別フィールドで保存する。確認によって元々の明示性を改変しない現行方針自体は保つ。

人は自動化された助言をヒューリスティックとして受け入れ、監視が不十分になるautomation biasを起こし得る（[automation biasの実験研究](https://journals.sagepub.com/doi/10.1177/154193129904300346)）。候補の事前提示は効率的だが、確認ボタンが妥当性の代用にならないUIが必要である。

### 4.3 P0: 「確信度」の意味が統計的confidenceではない

現行プロフィール値は、各assertionの `strength × confidence × explicitness係数 × provenance係数` を重複補正して集約し、さらに登録多様性を使って `confidence = max(P,N) × (0.55 + 0.45 × diversity)` とする。この値には次の性質がある。

- 真のラベルが正しい確率を推定していない
- 予測誤差との対応を検証していない
- assertion件数・根拠件数・登録の多様性に依存する
- 反証や欠測のモデルを持たない
- 同じ内容を重ねると上がる可能性がある
- 根拠の正しさではなく、根拠を追跡できる形式を強く評価する

LLMの自己申告confidenceも一般に校正済みとは限らず、専用の評価・校正が必要である（[AAAIのLLM confidence calibration研究](https://ojs.aaai.org/index.php/AAAI/article/view/34120)）。現行UIの「確信度 82%」は、利用者に「82%の確率で正しい」と読まれるおそれがある。

改善:

- 直ちに表示名を「根拠支持度」または「登録内支持度」へ変更し、百分率記号を外す。
- `positiveSupport`、`negativeSupport`、確認済みidentity数、作品数、根拠種別を分けて表示する。
- `stable` を「安定」ではなく「複数登録で反復」など観察事実に近い語へ変更する。
- 将来、正答確率を表示する場合だけ、凍結評価データでBrier score、Expected Calibration Error、reliability diagramを評価して校正する。

### 4.4 P0: 集計とfreshnessの不完全さ

#### 価値スタンス

嗜好プロフィールはidentity・work重複補正を行うが、価値スタンス表示は生の件数であり、同一キャラクターを繰り返すほど増える。スナップショットもstance assertionごとに1項目を作る。両者で証拠単位が異なるため、利用者は同じ尺度だと誤解し得る。

#### evidence set hash

プロフィールfreshness用hashは主に嗜好assertion ID、revision ID、状態、Ontology keyから作られ、価値スタンスの内容、根拠内容、確認変更、計算版の全要素を十分に含めない。内容が変わったのにfreshと判定される余地がある。

#### 根拠多様性

diversityの根拠件数は、同一entry・同一fragmentに由来する重複根拠も数え得る。件数が多いことと独立な情報源が多いことは別である。

改善:

- 価値スタンスにもentry → identity → workの同じ重複補正を適用し、分母・単位を表示する。
- hashへassertion・stance・evidenceの内容hash、review決定、Ontology版、algorithm版を含める。
- 根拠多様性はsource document、fragment、独立情報源でdeduplicateして数える。
- `profile_patterns` を実装するまでは、patternや一般法則を示すUI文言を使わない。

### 4.5 P1: 語彙の内容妥当性が未確認

94属性は広いが、現在のdefinitionは同語反復に近く、境界と除外条件がない。たとえば以下はラベル付けが揺れやすい。

- `morality.evil`、`morality.immoral`、`evil.affirms`、`evil.enjoys_cruelty`
- `personality.cold`、`warmth.indifferent`、`goodness.indifferent`
- `duality.inconsistent` と、物語上の描写不整合
- `role.villain`、`role.antagonist`、`morality.villainous`
- `aesthetic.nonhuman` と、人外的能力・人格

44反応経路も包括的に見えるが、利用者がその違いを安定して理解できるか、重要な経路が漏れていないか、1つの候補に複数経路をどう付けるかを検証していない。タグが44個あることは、44の構成概念が測定できていることを意味しない。

改善手順:

1. 多様な利用者に半構造化インタビューを行い、実際の「好き」の語りから概念を抽出する。
2. メディア心理、心理測定、ナラティブ研究、ファンダム研究の専門家と当事者が、関連性・網羅性を評価する。
3. 認知インタビューで、ラベルと説明をどう解釈したか、選びにくい組合せを確認する。
4. 属性ごとに定義、包含例、除外例、隣接概念との区別、判定可能な証拠をannotation guidelineとして作る。
5. pilotで選択頻度、欠測、重複、理解不能率を確認し、語彙を削除・統合・分割する。
6. 研究利用する尺度部分だけは、複数設問を用意し、因子構造・信頼性・収束的／弁別的妥当性・測定不変性を検証する。

### 4.6 P1: LLM分析精度を測っていない

現在の102テストは、schema、状態遷移、計算契約、認証などの回帰を検出する。実際の作品記述に対して「冷淡」「同一化」「悪を肯定」などを正しく抽出したかは測らない。LLMテキストアノテーションはタスク、データ、prompt、モデル版により性能と再現性が変わるため、システム固有の検証が必要である（[LLM annotationの横断評価](https://arxiv.org/abs/2306.00176)、[再現性・脆弱性の検討](https://pmc.ncbi.nlm.nih.gov/articles/PMC11954583/)）。

また、現行provider間でモデル、temperature対応、検索能力が異なる。offline replay、Workers AI、OpenAIで同一品質とは仮定できない。モデル名・prompt hashの保存はよいが、provider別の性能表が必要である。

### 4.7 P1: 好きなキャラクターだけでは選好を同定しにくい

任意に思い出して登録した「好きなキャラクター」は、好みだけでなく次に左右される。

- その作品を見たかという露出
- 登録時に思い出しやすいか
- 作品・キャラクターの人気
- 最近接触したか
- 登録するほど言語化しやすいか
- 同じシリーズを多く見ているか

好きな対象だけを観測しても、ある属性を「好む」のか、単に観測機会が多いのか、他属性との組合せが効いたのかは分からない。好きなキャラクター内の「苦手な要素」は有用だが、嫌い・中立なキャラクターとの比較の代わりにはならない。

改善:

- 任意で「好き」「中立」「苦手」の対象を同じ入力形式で登録できるようにする。
- 同一作品内で、複数キャラクターから選ぶ比較課題を用意する。
- 近い候補間のpairwise comparison、またはBest–Worst Scalingを補助的に使う。
- 視聴・読了の有無、接触時期、好きになった時期、対象範囲を保存する。
- 個人内の記述ツールと、集団レベルの予測モデルを別製品目的として分ける。

Best–Worst Scalingは、複数項目から最も当てはまるものと最も当てはまらないものを選ばせ、単純な評定尺度とは異なる比較情報を得る方法である（[Best–Worst Scalingの信頼性研究](https://aclanthology.org/anthology-files/pdf/P/P17/P17-2074.pdf)）。ただし回答負荷が増えるため、詳細モードに限定するのがよい。

### 4.8 P2: 時間・場面・社会文脈をモデル化していない

現行は好きな時期・場面を自由記述できるが、プロフィールdimension keyのcontextはLLM生成JSON全体に依存する。表現揺れで同じ文脈が分裂し、利用者が直接編集できない。逆に、時点変化を縦断的に分析する構造もない。

改善:

- `work phase`、episode、scene、年齢・形態、初見／再視聴、登録時点を構造化する。
- 集計keyに使うcontextは、利用者が確認した統制項目だけにする。
- LLM自由文contextは説明用に残し、集計keyから分離する。
- 同じ対象を時点・場面ごとに反復記録できるようにする。
- 必要ならevent-contingentまたはtime-contingentな短い記録を導入する。経験サンプリング法は、日常の経験を反復・その場で測ることで回顧バイアスを減らし、個人内変化を扱う方法である（[experience sampling method overview](https://pmc.ncbi.nlm.nih.gov/articles/PMC2773515/)）。

## 5. 推奨する検証計画

### 5.1 先に固定する主張

検証対象は、製品が何を主張するかで変わる。最初の正式な主張は次の範囲が現実的である。

> 利用者が登録・確認した好きなキャラクターについて、繰り返し現れる属性と反応経路を、根拠とともに整理して表示する。

「性格を当てる」「将来好きになるキャラクターを予測する」「無意識の本心を発見する」は別の研究課題であり、現行データだけでは支持できない。

### 5.2 凍結評価データセット

最低限、次を層化して含むデータを作る。

- 既成、既成（カスタム）、オリジナルの3方式
- 主人公、脇役、悪役、アンチヒーロー、人外、登場範囲限定
- 明示的な好き・苦手理由あり／なし
- 主要9経路と詳細35経路
- 正、負、混合polarity
- 公開情報、利用者入力、モデル知識、引用不能ケース
- 同名異作品、同一人物の媒体・時期違い、曖昧なentity
- LLMが棄権すべき根拠不足ケース

公開事実と利用者の内的反応は正解作成者が異なる。キャラクター理解は作品に詳しい独立評定者2名以上がラベルし、不一致を第三者が調停する。嗜好・価値スタンスは利用者本人の確認を最終基準とし、外部評定者が本人の感情を「正解」と決めない。

個人情報や性的・価値的反応を含み得るため、研究として収集する場合は目的、保存期間、二次利用、撤回、匿名化を明示し、必要に応じて倫理審査を受ける。

### 5.3 評価単位と指標

| 層 | 主な評価指標 |
|---|---|
| entity・作品同定 | exact match、候補提示recall、誤merge率、誤分離率 |
| 出典 | source種別精度、pointer正解率、引用範囲一致、verification false-positive率 |
| キャラクター理解 | 属性keyのmacro precision・recall・F1、scope一致、不要assertion率、欠落率 |
| 嗜好抽出 | 属性key・polarity・反応経路のmacro F1、本人による採用・修正・追加率 |
| 価値スタンス | orientation・stance別macro F1、道徳的支持への誤変換率 |
| 評定者一致 | Krippendorffのalpha等。複数ラベル・欠測に合わせて選ぶ |
| 再現性 | 同入力・同モデル、同入力・別run、provider別の一致率と分散 |
| 校正 | Brier score、ECE、reliability diagram。確率を表示する場合のみ必須 |
| 集計 | 重複登録・削除・修正に対する感度、順序不変性、snapshot再現性 |
| 利用可能性 | 説明理解率、訂正完了率、見落とし率、所要時間、認知インタビュー |
| 安全性 | 人格・病理の不当推測、悪役好意の価値支持化、根拠なし断定の件数 |

accuracyだけでは、多数派属性を当てるだけで高くなる。94属性・44経路の頻度差を考慮し、macro指標とラベル別結果、棄権性能を必ず併記する。

### 5.4 合格基準の決め方

先に都合のよい数値を置かず、pilotで人間同士の一致度と利用目的を測ってから決める。推奨順序は次のとおりである。

1. annotation guidelineを凍結する。
2. 人間同士の一致度を測り、曖昧な語彙を改訂する。
3. 人間一致を実用上の上限として、モデルbaselineを測る。
4. 利用者に害の大きい誤りをcritical setとして分離する。
5. モデル・prompt変更前に、用途別の最低値と許容退行幅を登録する。

critical setでは、現実人格・病理の断定、本人が否定した価値支持、別キャラクターの混同、存在しない引用などを0件目標にする。一般F1の高低で重大エラーを相殺しない。

## 6. 実装ロードマップ

### P0: 表示・訂正・データ整合性

1. 修正後summaryを再構築し、削除内容が次段へ漏れないようにする。
2. 理解assertion編集時にontology mappingを再選択させる。
3. 嗜好候補・価値スタンスの追加と編集、「判断不能」を実装する。
4. 非空候補の強制と `person_liking` 初期選択を見直す。
5. 「確信度%」を「根拠支持度」に改称し、構成要素を分けて表示する。
6. 価値スタンス集計とfreshness hashを修正する。
7. 上記の結合テストを追加する。

### P1: 検証可能な分析器

1. Ontology・反応経路のannotation guidelineを作る。
2. 利用者・専門家による内容妥当性と認知インタビューを実施する。
3. 凍結gold set、二重評定、調停手順を作る。
4. provider・モデル・prompt版ごとの精度、棄権、再現性を自動評価する。
5. 好き・中立・苦手、比較課題、露出・時点情報を任意入力として追加する。
6. entityと作品内scopeの照合を強化する。

### P2: 研究機能・発展機能

1. validated scaleを用いる任意の研究モードを、日常のタグ入力と分けて実装する。
2. 縦断記録と変化分析を実装する。
3. `profile_patterns` を、事前定義した仮説または探索的分析として実装する。
4. 利用者訂正を評価データへ還元する。ただし同意、匿名化、学習・評価データ分離を行う。
5. 言語・文化・年齢層ごとの測定不変性を検証する。
6. 予測機能を作る場合は、記述プロフィールとは別モデル・別評価・別同意にする。

## 7. UIと説明文の推奨表現

| 現行・避けたい表現 | 推奨表現 |
|---|---|
| あなたの本当の好み | 確認済みの登録から見える傾向 |
| 確信度 82% | 根拠支持度 0.82／複数登録で反復 |
| 安定した嗜好 | 3キャラクター・2作品以上で反復 |
| 科学的に分析 | 独自ルールで整理。心理尺度としては未検証 |
| あなたは冷淡な人物が好き | 登録内では、冷淡さへの正の反応候補が見られる |
| 悪を好む | フィクション上の逸脱への魅力が確認された。現実での支持とは別 |
| AIが判断しました | AI候補。根拠を確認し、違う場合は修正してください |
| 根拠がないため失敗 | この登録からは傾向を特定できませんでした |

## 8. 結論

現行システムの最もよい点は、「キャラクター名から利用者の性格を当てる」という過剰な約束をせず、対象理解、利用者解釈、反応経路、価値スタンス、根拠、確認を分けたことである。これは学術文献が示す複雑さを、かなり丁寧に実装へ写している。

最大の課題は、その豊かな分類が**測定済みであるように見えること**である。94属性・44経路、0〜1スコア、百分率の確信度、stable判定は、見た目上は精密でも、内容妥当性、正解データとの一致、再現性、校正をまだ持たない。まずP0の訂正整合性と表示上の過剰解釈を直し、次に人間基準の評価データと内容妥当性調査を作るべきである。

この順序で改善すれば、現行の強みである追跡可能性と人間確認を活かしながら、「面白いAI解釈」から「限界を明示した、検証可能な嗜好整理器」へ進められる。
