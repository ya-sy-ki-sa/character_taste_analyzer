# DD-11 属性辞書・嗜好集計詳細設計

## 1. 結論

嗜好属性は「すべてシステム固定」にも「すべて自由語」にもしない。次の3層を同時に保存する。

1. 解析軸を失わない固定core category/meta attribute
2. version管理し追加・統合・廃止できる統制AttributeDefinition
3. ユーザーとLLMの原語であるRawAttributeMention

未知語を既存属性へ強制mappingしない。`unmapped`の自由語のまま表示・集計・生成選択できる。特に悪、非道徳、善への無関心、残酷さ、支配、改心拒否等を「知性」「悲劇性」等へ置換しない。

## 3. 語彙life cycle

```text
raw mention
  ├─ exact/alias candidate ─→ accepted mapping
  ├─ semantic candidate ───→ user/operator review ─→ accepted/rejected
  └─ no safe mapping ──────→ user-scoped emergent attribute

emergent → reviewed → managed
                  ├→ merged(replacement)
                  ├→ split(mapping rules)
                  └→ deprecated(replacement optional)
```

- automatic acceptは完全一致aliasかconfidence 0.92以上かつambiguityなしだけ
- 0.70〜0.92は候補提示、0.70未満はunmapped
- morality/value/goodness categoryはsemantic similarityだけでautomatic acceptしない
- mapping変更でraw mentionを書き換えない
- ontology version間のmigration tableを作り、過去snapshotは当時versionを保持する

## 5. Profile集計対象

次をすべて満たすPreferenceAssertionを対象とする。

- ownerのactive entryのcurrent revisionに属する
- statusが`confirmed`または訂正後のcurrent assertion
- superseded/rejectedでない
- 対象CharacterIdentity/Representationが削除されていない
- attribute mappingがaccepted、またはraw labelが存在する
- context schemaがvalid

ValueStanceAssertionは通常dimensionと別系列で集計する。生成feedbackは明示的反映後に作られたPreferenceAssertionだけを対象にする。

## 6. 正規化keyと重複除去

```text
dimensionKey = attributeKey | raw:{normalizedLabel}
             + polarity
             + responseChannel
             + conditionHash
```

`conditionHash`はcanonical JSONのSHA-256。空条件と条件付きは別dimensionとする。

同一entry revision・dimension keyの複数assertionは、同じ言い換えを数えないため最大寄与値だけ採用する。positive/negative/mixedは別に保持する。mixedはpositiveとnegative双方へ0.5倍で寄与し、相殺しない。

## 7. 単一assertion寄与

`s`=strength、`c`=confidence、`e`=explicitness weight、`q`=evidence qualityとする。

| explicitness | `e` |
|---|---:|
| user_explicit | 1.00 |
| user_confirmed | 0.95 |
| inferred | 0.55 |
| model_knowledge | 0.25 |

`q`は根拠の由来の道徳性ではなく追跡可能性で決める。

| evidence | `q` |
|---|---:|
| user input/reviewに直接anchor | 1.00 |
| source fragment直接支持 | 0.90 |
| source interpretation | 0.75 |
| model knowledgeのみ | 0.45 |
| 根拠なし | 0.20 |

```text
baseContribution x = clamp01(s × c × e × q)
mixedContribution  = 0.5 × x （positive側とnegative側へ別々に加える）
```

`moral_valence`、hero/villain、good/evilを係数に使わない。

## 8. 派生・作品偏り補正

同じcharacterのfacetや二次創作を大量登録して1票ずつ数えない。一方、同じidentityに複数の明示根拠がある事実は完全には捨てない。

寄与値集合`X`を降順にし、次でgroup aggregateを求める。

```text
discountedUnion(X, d):
  m = max(X)
  rest = X without one maximum
  return m + d × (1 - m) × (1 - Π(1 - x for x in rest))
```

集計順:

1. entry内重複: `max`
2. 同一CharacterIdentity内: `discountedUnion(X, 0.25)`
3. 同一Work内の異なるidentity: `discountedUnion(X, 0.50)`
4. 異なるWork間: `1 - Π(1 - workContribution)`

original characterでworkがない場合は、identityごとに仮想work groupを作る。customized representationはbaseと同じidentity groupに入る。

## 9. score・confidence

positiveとnegativeを別々に前節で集計し、`positiveScore=P`、`negativeScore=N`とする。

```text
identityDiversity = min(1, distinctIdentityCount / 3)
workDiversity     = min(1, distinctWorkGroupCount / 2)
evidenceDiversity = min(1, traceableEvidenceCount / 5)
diversity         = 0.40 × identityDiversity
                  + 0.35 × workDiversity
                  + 0.25 × evidenceDiversity
confidence        = clamp01(max(P, N) × (0.55 + 0.45 × diversity))
```

値は保存前に小数6桁へroundする。表示は百分率へ変換するが、「好みの確率」と表現しない。

classification:

| classification | 条件 |
|---|---|
| `stable` | `max(P,N) >= 0.65`かつ`confidence >= 0.65`かつidentity 3以上かつwork group 2以上 |
| `emerging` | `max(P,N) >= 0.35`、またはuser explicit contribution 0.50以上 |
| `insufficient` | 上記以外 |

単一キャラクターへの明示的な強い好みは`emerging`として明瞭に表示するが、一般的傾向を意味する`stable`にはしない。

## 10. Value stance集計

keyは`targetType + normalizedTargetRef + orientation + scopeHash`とし、stanceごとのscoreを別に保存する。affirmとreject、indifferentを一軸上で相殺しない。

```text
stanceContribution = confidence × explicitnessWeight × evidenceQuality
stanceScore = 派生・作品補正後のunion
```

`stance=unspecified`は「支持していない」ではなく「判断材料なし」としてcoverageだけに数える。ユーザーの`indifferent`と対象の`orientation=indifferent_to_good`は別fieldで表示する。

## 11. 条件付き嗜好

- 集計条件には、ユーザーが登録時に明示した「特定の時期・場面・状態」だけを使う
- LLMが生成した`contextText`はassertion/evidenceの説明として保持し、dimension keyには使わない
- ユーザー指定がない状態（キャラクター全体）と、明示された状態は別dimensionにする
- 同一attributeの異なるユーザー指定範囲は別dimension
- narrower contextをbroaderへ自動一般化しない
- UIでは同一attributeを1行へまとめ、response channelと指定範囲を併記する。内部scoreは混ぜない
- LLM由来のfreeTextは表示・生成・根拠確認に使えるが、集計条件として扱わない

例: 「悪役なら傲慢さが好き」と「傲慢さが常に好き」は別dimensionである。

## 12. Pattern抽出

Patternは説明候補であり、因果関係ではない。

### 12.1 Co-occurrence

同じidentity group内で2 dimensionが共に寄与0.30以上となる集合を使う。

```text
weightedJaccard(A,B) = Σ min(a_i,b_i) / Σ max(a_i,b_i)
```

distinct identity 3以上、distinct work group 2以上、weighted Jaccard 0.45以上でcandidateとする。

### 12.2 Contrast

同一attributeにpositive/negative双方0.40以上あり、context hashが異なる場合にcontrast candidateを作る。「矛盾」ではなく「条件によって反応が異なる」と表示する。

### 12.3 Representation-specific

同じidentityのbaseとcustom/facetで寄与差0.35以上の場合に候補化する。これにより、キャラクター全体ではなく片方の人格・一場面だけが好きな状態を保持する。

### 12.4 Pattern confidence

```text
patternConfidence = patternScore
                  × min(1, identityCount / 4)
                  × min(1, workGroupCount / 3)
```

0.60以上を表示候補、0.40〜0.60を「データ不足を伴う候補」、0.40未満は通常画面へ出さない。ユーザーはconfirm/rejectできる。

## 13. 時間変化

初期scoreに時間減衰を適用しない。古い好みを自動的に消さないためである。履歴画面では直近90日とそれ以前の寄与を同じ式で別集計し、差0.20以上を「最近のデータでは強い/弱い」と説明する。

entry archive、訂正、feedback取消による変化は`profile_generation`間の差分として示す。

## 14. Profile表示順

```text
rankScore = max(P, N) × confidence
          × classificationFactor
classificationFactor: stable=1.0, emerging=0.8, insufficient=0.5
```

同点はevidence count降順、stable key昇順。悪・善、hero・villain、main・minorをrank係数へ使わない。

## 15. Evidence set hash

集計入力を次で昇順sortしcanonical JSON化してSHA-256を取る。

```text
assertionId, assertionContentHash, latestReviewId,
entryRevisionId, entryStatus, ontologyMappingId,
correctionVersion, algorithmVersion
```

同じhashとalgorithm versionならProfileProjection結果は一致しなければならない。LLMは集計経路に入れず、pattern labelをLLMで整形してもscore/hashの意味を変えない。

## 16. Algorithm version

初期値は`profile/v1.0.0`とし、LLM生成文によるdimension分割を廃止した版を`profile/v1.1.0`とする。

- 係数・閾値変更: minor以上、全profile再構築
- bug fixで出力が変わる: patch、影響userを再構築
- dimension keyの互換性破壊: major

新旧世代を上書きせず、ProfileProjectionを追加して比較可能にする。生成済みProfileSnapshotは再計算しない。

## 17. 実装疑似コード

```typescript
function buildProfile(assertions: CurrentPreferenceAssertion[]): ProfileProjection {
  const normalized = assertions.map(normalizeAndWeight);
  const deduplicated = maxByEntryAndDimension(normalized);
  const dimensions = groupByDimension(deduplicated).map(group => ({
    ...aggregatePositiveAndNegativeSeparately(group),
    ...calculateDiversityAndClassification(group)
  }));
  const patterns = derivePatterns(dimensions, deduplicated);
  return validateProjection({ dimensions, patterns });
}
```

集計関数は純粋関数とし、固定fixtureに対して完全一致を検証する。
