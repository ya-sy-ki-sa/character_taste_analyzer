## 2. 実装上の暫定決定

### DEC-IMP-001 初期の機能範囲

手動確認可能な最初の縦断範囲を次に固定する。

1. 既存と同じUUID access keyによる登録・有効化・ログイン・変更・削除
2. existing / customized_existing / originalの3方式登録
3. 基本像とcustom deltaのLLM抽出、ユーザーreview
4. 嗜好・response channel・value stanceの抽出、ユーザーreview
5. 決定論的ProfileProjection、履歴、根拠表示
6. ブラウザ内GraphProjectionの描画・絞り込み
7. ProfileSnapshotとGenerationBriefからのオリジナルキャラクター生成・保存

R2直接upload、PDF OCR、永続vector storeは現行scopeに含めない。export用R2とEmbedding Provider境界だけを現行実装として保持する。

### DEC-IMP-002 review待ち

Workflow instanceの長期waitに業務状態を依存させない。抽出stepはD1のJobを`waiting_for_user`にして終了し、review APIが次の解析stepを新しい実行として開始する。これによりlocal、Cloudflare Workflow、Provider切替で同じ状態遷移を使う。

### DEC-IMP-003 Workers AI quota尽き

Workers AIのquota/429/availability失敗を`PROVIDER_CAPACITY_EXHAUSTED`または`EXTERNAL_PROVIDER_UNAVAILABLE`としてJobに保存する。未成功の出力を自動でFake成功に置き換えない。実装・単体テスト・E2Eは`replay`/`fake`で継続し、開発を中止しない。

### DEC-IMP-004 旧データ

新規作成前提のため旧D1 schemaのデータmigrationは作らない。ローカルD1も新しいdatabase nameを使い、旧データの表面上の混入を防ぐ。

実装時に、旧ローカルD1が暫定的なv2名と同じMiniflare識別子を使用していたことを検出した。旧DBを削除せず保全し、新版は`character-taste-lab-v2-clean-local`と専用local database IDへ分離する。

### DEC-IMP-005 Vite buildとlocal secret

Cloudflare Vite pluginはWorker build出力へ開発用`.dev.vars`を複製する。`dist`はGit管理外だが、配布前の秘密値残存を許容しない。全build scriptの末尾で、`dist`配下に生成された`.dev.vars`をpath検証後にすべて削除する。旧ビルド名の出力にも秘密artifactを残さず、削除scriptは`dist`外や別名fileを拒否する。Wranglerへ登録する本番secretはbuild artifactではなく`wrangler secret`で管理する。

### DEC-IMP-006 Account deletionとJob所有者

初期DDLの`jobs.owner_user_id ON DELETE SET NULL`は、同tableの「account_deletion以外はowner必須」というCHECK制約と競合した。ユーザー所有Jobはアカウント削除時に履歴を含めて削除する方針のため`ON DELETE CASCADE`へ修正する。現行の削除APIはUserを削除し、Jobを含む所有データはCASCADEで削除する。修正前DDL向けのJob先行削除は廃止した。
