## 2. 実装中に修正した設計不整合

1. D1 UnitOfWorkをcallback transactionではなく`batch()`用TransactionPlanへ変更した。
2. CharacterUnderstandingとPreferenceAnalysisのsummary、資料評価、不確実性の保存列を追加した。
3. profile rebuild時のProfileSnapshot reasonへ`profile_rebuild`を追加した。
4. customization deltaの`modify/invert/add/remove`とbefore/afterの意味制約をZodにも追加した。
5. `jobs.owner_user_id ON DELETE SET NULL`とowner必須CHECKの競合を`ON DELETE CASCADE`へ修正した。
6. 旧local D1との識別子衝突を、新版専用D1へ分離した。
7. Vite build出力へ複製される`.dev.vars`をbuild終了時に`dist`配下からpath検証して削除する処理を追加した。旧ビルド名の残存artifactも対象とする。
8. アカウント削除の確認名をUIだけでなくAPIでも検証し、クライアント迂回時の誤削除を防いだ。
9. 登録・生成の冪等ヒットでは既存resourceを返し、解析・生成workflowを再起動しないようにした。キーを異なるpayloadへ再利用した場合と、ユーザー作成キーを異なる名前で再利用した場合は409とする。
10. OpenAI Responses APIへ`store:false`、strict JSON Schema、出力上限、temperature、LLM処理の冪等キーを渡す契約testを追加した。
11. CharacterUnderstandingへ嗜好入力を混入させず、カスタム登録では基本像用資料と改変説明の役割を分け、確認画面にも基本像・対象像・差分を別表示する。
12. キャラクターdomainのD1操作を`CharacterTasteDataStoreStrategy`へ集約した。初期値は`d1`で、未実装Strategy名はfail-fastし、HTTP/Workflowで暗黙fallbackしない。
13. ForceAtlas2のWeb Workerだけに必要な`worker-src 'self' blob:`をCSPへ追加し、その他のscript source制限は維持した。APIはWorker middleware、配置時の画面本体はStatic Assetsの`_headers`で適用する。local ViteだけはReact Fast Refreshのinline preambleに必要な`script-src 'unsafe-inline'`も許可する。
14. route切替直後の幅0状態をSigmaで許容し、実表示後のresizeで描画する。E2Eは未処理のpage errorがないことも検査する。
15. 登録・ProfileSnapshotが0件の生成画面では、空の初期選択stateを再設定しない。空状態表示と未処理page errorがないことをE2Eで回帰検査する。
16. ヴィラン等の嗜好を価値判断せず保持する方針や、生成時に善性・贖罪等を自動補完しない方針は内部仕様とし、その説明文を一般ユーザー向け画面へ表示しない。
17. キャラクター登録時の必須`knownScope`入力を廃止し、特定の時期・場面・状態に限って好きな場合だけ記入する任意`preferenceContext`へ変更した。未入力時の内部scopeは「キャラクター全体」とする。
18. 必須`sourceText`入力を廃止して任意`referenceMaterial`へ変更した。既成キャラクターはWorker側の公開情報検索、モデル知識、OpenAI選択時の組み込みWeb検索から基本像を構成し、ユーザー資料とユーザー自身の解釈を別入力として扱う。Replay/Fakeは外部検索しない。
19. オリジナル登録に必須`characterBasicInfo`を追加した。既成キャラクターのシステム収集済み公開情報に対応する基本像入力として解析・SourceSetへ渡し、任意`referenceMaterial`と`userCharacterView`は別の役割で保持する。
20. 「どういう意味で好きか」を調査資料の概念区分に基づく44種類へ拡張した。一般的な9項目を常時表示し、詳細35項目を7カテゴリのaccordionに分けた。UI、入力schema、LLM定義、Profile・Graph表示、D1 CHECK制約は共通catalogへ整合させた。
21. キャラクター登録の解析失敗カードへ、LLM応答形式、Provider拒否、外部出典・根拠検証の日本語分類と`error_detail_safe`を表示するようにした。JSON解釈不能時も安全な応答抜粋をJob・attempt・model runへ記録し、APIの`EntrySummary.job.errorDetail`から表示する。
22. OpenAIのrefusal・failed・incomplete・content filter signalと、アプリケーション独自の出典allowlist違反を区別した。`x-request-id`、Response ID、応答status、error、未完了理由、refusal、HMAC化`safety_identifier`をmodel runへ保存し、下流の根拠検証で失敗しても完了済みattemptを保持するmigration 006を追加した。
23. CharacterResearchを日本語WikipediaとWikidataの2系統へ拡張した。作品・人物の直接一致または一致済みWikipediaの`wikibase_item`連携を必須とし、取得providerと採用理由を保存する。URLの追跡parameter・fragment・末尾slashだけを正規化し、未取得URLやドメイン全体は許可しない。
24. カスタム解析の前段が成功し後段が未完了になった場合に、前段のResponse ID・`completed`状態を後段エラーへ誤結合する不具合を修正した。失敗attempt自身のrequest/response ID・status・token usageを優先し、解析の出力上限を5,000から100,000へ変更した。既存の対象Jobは正しい診断へ修復し、再試行可能へ戻した。

詳細な判断理由は[DD-17](17_実装前監査・暫定決定.md)に記録する。

## 5. 手動確認手順

1. `npm run db:migrate:local`を実行する。
2. 実Providerなら`npm run dev`、quotaを使わない場合は`npm run dev:offline`を実行する。
3. ユーザーを作り、UUID access keyを保存して有効化・loginする。
4. キャラクター画面で3方式のいずれかを登録する。
5. 「基本像の確認待ち」で抽出内容を確認し、嗜好解析へ進む。
6. 「嗜好候補の確認待ち」で個々の好き候補・価値スタンスを必要に応じて削除し、残りをprofileへ反映する。
7. 嗜好解析結果でdimension、value stance、browser graphを確認する。
8. 作成画面で使用／禁止項目とmodeを選んで生成する。改心・贖罪と隠れた善性は画面項目から削除され、必須として自動追加しない内部既定を使う。

## 6. 注意事項

- local D1の旧データは削除していない。新版専用IDへ分離している。
- `npm run db:migrate:local`は新版D1だけへ適用する。
- Workers AI capacity失敗時も登録入力はD1に残る。offlineへ切り替えて別の検証を続けられる。
- review UIは理解属性・カスタム差分の修正／追加／削除と、好き候補・価値スタンスの個別削除に対応する。嗜好候補の個別修正・追加は未実装であり、必要な場合は入力を見直して再分析する。
- 現在の画面は`/api/v1`のEntry登録、snapshot/run単位reviewを使用する。目標OpenAPIにだけ残る旧assertion単位routeはas-built契約ではない。
