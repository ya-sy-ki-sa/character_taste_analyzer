# DD-15 テスト・評価詳細設計

## 1. 品質方針

本システムでは「schemaがvalid」だけでなく、根拠、scope、ユーザー訂正の優先、道徳的中立、削除可能性まで品質対象とする。LLMを含む非決定処理は、決定論的validator、replay fixture、人手評価を組み合わせる。

## 2. Test level

| level | 主tool | 対象 |
|---|---|---|
| static | TypeScript、Biome、OpenAPI/JSON Schema validator | 型、lint、schema参照 |
| unit | Vitest | domain rule、集計、mapper、capacity |
| property | fast-check等 | hash、cursor、集計範囲、不変条件 |
| contract | Vitest shared suite | Repository、Provider、BrowserGraphEngine |
| integration | local D1/Miniflare、fake R2/Queue/Workflow | transaction、binding、retry |
| component | Testing Library | form、review、error、a11y |
| E2E | Playwright | 主要user journey |
| LLM eval | frozen fixture＋Provider replay/live sample | 抽出、根拠、道徳中立 |
| performance | local load harness、browser performance | API/query/graph |
| security | dependency scan、manual abuse cases | auth、CSRF、IDOR、prompt injection |

live external Provider testは通常CIで実行しない。nightly/manualで予算付き実行し、merge gateはreplayで安定させる。

ローカルのブラウザ手動確認は`LLM_PROVIDER=workers_ai`を既定とし、実際の抽出・生成応答を含めて確認する。Vitest、Playwright自動E2E、CIは`replay`または`fake`を明示設定し、Workers AIのnetwork/quota/応答変動をmerge gateへ入れない。

### 2.1 LLM Provider共通契約test

`OpenAiLlmProvider`、`WorkersAiLlmProvider`、`ReplayLlmProvider`、`FixtureLlmProvider`は同一のcontract suiteを通す。live呼出し不要なHTTP/Binding stubで、次を検証する。

- 全operationのrequestがProvider固有formatへ変換され、共通schema candidateとmetadataに戻る
- schema違反、timeout、429、5xx、authentication失敗、policy rejectが共通errorへ写像される
- OpenAIのResponses／EmbeddingがProvider Native endpointと`cf-aig-authorization`を必ず使用する
- Workers AIはGateway ID付き`AI` binding以外を通じてsecretやユーザーデータを公開しない
- API key、prompt/response本文がlogへ含まれない
- fallback対象/非対象errorと、呼出しごとのmetadata分離がDD-10と一致する

OpenAIとWorkers AIの少数live sampleは各Provider/modelの採用時、model更新時、preview公開前にmanual実行する。両者とも同じcritical fixtureの意味保存ゲートを緩和しない。

## 3. Test dataの作り方

### 3.1 原則

- 実ユーザーdataをfixtureへ使わない
- 既存作品の全文・長い台詞をrepositoryへ保存しない
- public domain、ライセンス許諾、短い検証用引用、完全synthetic characterを使う
- character理解fixtureとuser嗜好fixtureを分離する
- labelだけ変えた近似例ではなく、役割・道徳・scope・response channelを交差させる
- 正解は最低2名のreviewまたは、1名作成＋別時点reviewで確定する

### 3.2 Fixture package

```text
test/fixtures/
├─ characters/{fixtureId}/
│  ├─ manifest.json
│  ├─ sources/*.md
│  ├─ entry.json
│  ├─ expected-understanding.json
│  ├─ expected-deltas.json
│  └─ notes.md
├─ preferences/{fixtureId}/
│  ├─ user-input.json
│  ├─ expected-preferences.json
│  └─ expected-value-stances.json
├─ profiles/{fixtureId}/
│  ├─ assertions.json
│  └─ expected-profile.json
├─ generation/{fixtureId}/
│  ├─ profile-snapshot.json
│  ├─ request.json
│  ├─ expected-brief.json
│  └─ validation-cases.json
└─ llm-replays/{provider}/{model}/{promptVersion}/
```

manifest:

```typescript
interface EvalFixtureManifest {
  fixtureId: string;
  license: string;
  sourceOrigin: "synthetic" | "public_domain" | "licensed" | "short_quotation";
  axes: string[];
  expectedAmbiguities: string[];
  prohibitedInferences: string[];
  reviewerIds: string[];
  approvedAt: string;
}
```

## 4. 必須fixture matrix

最低48組とし、各axisの単独例だけでなく交差例を含める。

| axis | 必須case |
|---|---|
| narrative role | hero、villain、antihero、antagonist、supporting、minor、scene-limited |
| morality | good、evil、immoral、amoral、indifferent-to-good、mixed、self-defined |
| villain expression | pure evil、tragic、comic、competent、incompetent、victorious、unpunished |
| change | redemption、failed redemption、no redemption、corruption、flat |
| representation | whole、medium、period、facet、scene、transformative、user interpretation |
| customization | add、modify、remove、invert、narrow scope、emphasize、inherit |
| evidence | rich primary、conflict、secondary only、user only、model knowledge only、unknown |
| preference | explicit reason、unknown reason、mixed、negative、condition-only |
| response | moral supportあり/なし、love-to-hate、root-for、transgression、no-redemption |
| role prominence | central、side、minor、silent/background |

保護対象の意味変化case:

- 「悪そのものが好き」→知性・悲劇性だけへ置換しない
- 「善に関心がない点が好き」→隠れた優しさを追加しない
- 「行為には反対だが人物は好き」→moral supportにしない
- 「悪役に勝ってほしい」→現実の加害支持にしない
- 「改心しないでほしい」→redemption wishに反転しない
- 「一場面の人格だけ好き」→character全体へ一般化しない
- 「端役が好き」→中心人物として生成し直さない

## 5. Unit test

### 5.1 Auth/security

- username Unicode正規化、大小文字unique、境界長
- deterministic user/key/session/CSRF derivationの回帰vector
- digest inputのNUL separator、pepper差、定時間比較
- pending期限、active条件、session 30日、7日以下renew
- credentialがユーザーごとに1件で、generation列を持たない
- Origin/CSRF、SameSite cookie、logout idempotency
- rate limit window境界、IP pseudonym rotation

### 5.2 Domain/state

- 3 registration typeの不変条件
- customのbase必須、cycle、深度8
- append-only revision/snapshot
- Entry/Job/Generationの全合法・不正遷移
- correctionによるsupersede、archiveによるprofile除外
- owner境界、削除中userのcommand拒否

### 5.3 Attribute/profile

- alias exact/candidate/unmapped境界0.92/0.70
- morality categoryのsemantic auto-accept禁止
- `villain != evil != antagonist`
- `indifferent stance != indifferent_to_good orientation`
- dimension key/canonical context hash
- entry max、identity discount 0.25、work discount 0.50
- positive/negative非相殺、mixed両側0.5
- explicitness/evidence weightの全組合せ
- stable/emerging/insufficient境界
- time decayなし、履歴差分
- algorithm version/evidence set hash決定性

property:

- score/confidenceは常に0〜1
- evidence追加で同一極性scoreが低下しない
- 同じassertionの複製でentry寄与が増えない
- assertion順序で結果が変わらない
- moral valenceを変えても他field同一ならscoreが変わらない

### 5.4 Generation/graph/capacity

- brief selection、conflict、non-requirement必須
- value policy violation、部分修正pointer保全
- similarity threshold境界
- graph node/edge一意性、dangling edge拒否、page一致
- browser filter/path/neighborのpure function
- 70/85/90% capacity境界、予約容量、縮退順
- usage stale時conservation、UTC reset

## 6. Repository contract/integration

DD-07の共通suiteに加え次を検証する。

- D1 foreign key/check/uniqueがdomain不正値を拒否
- main record＋outbox insertの原子性
- batch途中errorで0件commit
- owner Aのresource IDをowner Bがread/update/deleteできない
- cursorに同じtimestampが並んでも欠落・重複しない
- stale revisionは409相当error
- SourceSetVersionとSnapshotが過去revisionを固定
- account削除後にowner FK recordが0
- `EXPLAIN QUERY PLAN`で主要queryが想定indexを使用

DDL migration test:

1. 空DBへ全migration
2. 前version fixture DBへincremental migration
3. migration再実行が安全に失敗/skip
4. `PRAGMA foreign_key_check`が0行
5. table/index一覧goldenとの比較

## 7. Workflow/Queue integration

- Workflow開始event重複でJob/Workflowが一つ
- 各step直前/直後の擬似failureから再開
- LLM timeout、429、5xxのbackoff
- schema repair 2回後terminal failure
- review wait/resume、古いreview世代409
- stale input generationがcurrentを上書きしない
- Queue message重複でvector/objectが重複しない
- Queue 24時間expire後にD1 Outboxから再送
- dead event手動再送のaudit
- cancellation可能状態とaccount deletion cancel禁止

failure injection pointは各stepに安定IDを付け、test configurationから一度だけ例外を投げる。

## 8. API contract test

- OpenAPI request/response validation
- mutationのIdempotency-Key/CSRF不足
- authなし/他owner/削除中user
- validation error JSON Pointer
- If-Match競合
- 200/201/202/204のbody規則
- list cursor、limit最大、stable sort
- capacity 429とretryAfter
- errorに内部SQL、Provider本文、secretが含まれない
- Graph external schemaとenvelopeの一致

CIでOpenAPI `$ref`解決、operationId一意、全path parameter定義、全success response schemaを検査する。

## 9. Component/E2E

### 9.1 Auth

- user作成→一度だけkey表示→有効化→login
- key未保存から戻る警告
- session renew/logout/re-login
- pending期限、Turnstile error、rate limit

### 9.2 Registration/analysis

- existing: work/character/scope/source→基本像review→嗜好review→active
- customized: base選択→対象scope/改変→base像→delta→嗜好
- original: sheet validation→理解→嗜好
- sourceなしprovisional、source競合、失敗retry
- user correction後のProfile/Graph更新

### 9.3 Profile/generation

- positive/negative/conditional/value stance/response channel表示
- evidence drill-down、history、list fallback
- graph keyboard、filter、neighbor、summary fallback
- snapshot固定→brief編集→generate→basis表示
- partial revision、similarity warning、feedback opt-in/cancel
- evil/no-redemption/minor-role生成で不要な善化・中心化なし

### 9.4 Data control/capacity

- export downloadと24時間失効
- account deletionでsession即失効、D1/R2/Vector/IndexedDB削除
- warning/conservation/restricted banner
- 高コスト停止中もread/review/export/delete維持

主要E2Eはdesktop Chromium、mobile viewport Chromium、Firefoxで行う。Safari相当はWebKitでsmokeする。

## 10. LLM evaluation

### 10.1 指標

| metric | 計算 | Release gate |
|---|---|---:|
| raw schema valid | repair前valid / run | 95%以上 |
| final schema valid | repair後valid / run | 99%以上 |
| evidence ID precision | 存在するevidence ID / 全出力ID | 100% |
| evidence support precision | 人手で支持 / 引用付き主張 | 95%以上 |
| CharacterAssertion macro F1 | fixture label/value/scope | 0.85以上 |
| Delta operation accuracy | operation完全一致 | 0.90以上 |
| Preference precision | 正しい嗜好候補 / 全候補 | 0.90以上 |
| ValueStance macro F1 | stance/orientation/scope | 0.88以上 |
| unsupported high confidence | 根拠なしconfidence>0.70 | 0件 |
| role/morality confusion | roleをmoralityへ誤写像 | critical fixture 0件 |
| over-moralization | 穏当化・善化・病理化 | critical fixture 0件 |
| correction overwrite | user訂正と矛盾する再出力 | 0件 |

F1等が閾値を満たしてもcritical fixtureの意味変化が1件あればrelease不可。

### 10.2 比較手順

1. baseline model/prompt/schemaのreplay resultを固定する。
2. candidateを全fixtureへ実行する。
3. JSON Schema/semantic metricを自動集計する。
4. changed assertion/value stance/generation部分だけblind reviewする。
5. axis別にregressionを確認する。
6. prompt/model version、sample数、cost、結果をeval reportへ保存する。

Provider model更新は同名aliasでもcandidate変更として扱う。

## 11. Generation eval

各briefに最低3 seed相当のcandidateを評価し、次を判定する。

- required satisfaction 100%
- prohibited/value policy violation 0件
- `briefCoverage` pointer valid 100%
- unexpected redemption/hidden goodness/punishment 0件（prohibited fixture）
- minor/scene-limited roleの中心化0件
- similarity blockの検出率95%以上、抽象属性単独のfalse block 0件
- partial revisionの非対象field hash一致100%

創造性は単一自動scoreでrelease判定しない。distinctiveness、coherence、preference fitを5段階blind reviewし分布を記録する。

## 12. Security test

- credential/session digestのDB leak想定
- login/user enumeration、Turnstile bypass、rate limit bypass
- CSRF、Origin spoof、CORS、cookie attributes
- IDOR全private endpoint
- stored/reflected XSS（character名、Markdown、LLM output）
- unsafe URL、file MIME spoof、oversize、zip bomb/PDF bomb
- prompt injectionをsource/user引用へ埋込み
- external `$ref`/SSRF相当のdocument processing禁止
- export/deletion tokenの再利用
- log/analytics/cacheへのprivate data leak
- dependency/license/security scan

LLM outputをHTMLとして描画せずtext node/許可Markdown sanitizerを使う。CSPはDD-04に従う。

## 15. CI gate

Pull request:

- format/lint/typecheck
- JSON/YAML/SQL parse、OpenAPI `$ref`
- unit/property/contract
- component
- migration from previous fixture
- LLM replay critical suite

main/release:

- preview integration/E2E
- security/a11y automated
- full LLM replay eval report
- query plan/performance smoke
- migration/restore rehearsal結果確認
