# 解析の判定境界と補完処理の改修

## 目的と根拠

ユーザーAの登録比較と、同一モデルによる切り分け実験で確認した問題を改修する。先行実験では価値態度の過剰な追加が判定境界の明記で減ったが、対象と反復数は限定されている。人物理解の情報不足には、根拠検証後に補完を再判定しない処理順序が関係していた。反応経路の定義は抽出と監査で共有されていなかった。

先行記録はローカルの `.artifacts/live-evaluation/20260912-user-a-prompt-spec-01` と `.artifacts/live-evaluation/20260912-user-a-diagnosis-01/diagnosis.md` に保存している。今回の改修で上書きしない。

自己類似については、文脈的な自己照合を認める範囲を先に定義する。人物とユーザーの心理が客観的に一致するという認定とは分ける。Fake・Replayの成功を実LLMの意味理解の改善実証にはしない。

## 実装計画

1. 通常版の反応経路カタログを抽出・監査の共通system指示へ組み込む。外見評価・作劇評価・憧れ・行動への願望の境界を共通化し、dark版へ通常版の経路を混入させない。
2. 好みと規範的な価値態度を分離する。自己照合はユーザーの主観として根拠付け、反応の否定とユーザー経験の人物事実への転用を禁止する。監査は入力との照合で取りこぼしも点検する。
3. 人物理解の根拠検証・正規化を補完判定より先に実行する。正規化した人物像と不足理由を補完へ渡し、補完・再監査は各stageにつき1回まで。補完後も不足する場合は、不足表示と根拠のある候補を保持する。
4. 反応のみ不明なら監査内でresponseChannelをnullへ改訂し、改訂後の命題を再評価する。既存の引用・scope・根拠集合の採用条件を緩和しない。
5. 回帰テスト、型検査、生成物更新と`npm run verify`を実施する。既存登録の自動再解析・DB移行・モデル変更は含めない。

## 検証項目

- 抽出・監査に同じ定義が届くこと、dark版の処理境界が保たれること。
- 正規化前に十分でも正規化後に不足した人物像に補完が走ること。
- 補完で回復する場合、回復しない場合、既に十分な場合の呼出回数と保存結果。
- 補完後の実行記録・原出力ハッシュ、通常版カスタムの基本像／変更後の分離。
- 反応未確定の候補が保存・集計まで保持され、根拠のない候補は除外されること。

## 実装結果

2026-09-12に計画1〜4を実装した。[嗜好プロンプト](../worker/llm/prompts/preference.ts)は`v3.9.0`、[意味監査](../worker/llm/prompts/semantic-audit.ts)は`semantic-integrity/v1.5.0`、[人物理解](../worker/llm/prompts/understanding.ts)は`understanding-information/v1.6.0`へ更新した。反応定義は共通system指示に集約し、ユーザー側メッセージの重複した定義を削除した。

[人物理解の呼び出し処理](../worker/features/analysis/llm-understanding.ts)では、検証・正規化した候補から補完を判定する。判定用と保存用は[共通の出典準備](../worker/features/analysis/understanding-provenance.ts)と同じ検証・正規化関数を使用する。根拠検証中の失敗にも、完了済みの実行記録と再試行可否を引き継ぐ。原出力ハッシュは正規化前の応答に対する値を保持する。

判定前の出典読み取り・検証は増える。LLM呼び出しは各stageにつき通常2回、補完時4回の上限を維持するが、従来見逃していた不足が補完対象になるため、その登録では呼び出し数・待ち時間が増える。

## 出典本文と監査後処理の追加改修

max再評価と `.artifacts/live-evaluation/20260912-user-a-max-diagnosis-01/diagnosis.md` に基づき、次の順で改修・比較する。

1. サーバー側の出典本文取得と既存URLのみの資料の更新を実装する。本文をLLM入力に追加せず、取得失敗と引用不一致を区別する。
2. プロンプトの既存5箇所を置換・短縮する。文脈照応、部分的な願望、人物事実とユーザー評価の分離、反応未確定時の再監査を明確にする。応援は勝利・成功だけに限定せず、人物への一般的な応援を含める。
3. 監査の対象不確定と出典照合不能を別理由で保存する。除外時の要約は採用結果から再構成し、LLMが付けた旧制約説明を引き継がない。機械的な一律質問は追加しない。LLM自身が提示した質問と監査履歴は保持する。
4. local/staging/productionのeffort指定を空欄へ戻す。新規ジョブでモデルの既定値を使う。既存ジョブの設定は変更しない。
5. 回帰・全体検証後、ユーザーAの同一15件を新しい評価用DBへ登録する。旧defaultとmaxの双方と比較し、プロンプト改修とeffort変更の単独効果とは結論しない。

嗜好は`v3.10.0`、意味監査は`semantic-integrity/v1.6.0`。JSONスキーマとLLM呼出上限は維持する。比較用`o200k_base`ではsystem指示が抽出6,596→6,574、監査8,214→8,172トークンに減少した。これは提供先固有のトークナイザーの保証ではない。文字数・UTF-8バイト数も減少し、予算を回帰テストに固定した。実際の総入力は生成された候補量や補完回数にも依存する。

本文取得はHTTPS公開ホスト、8秒、1 MB、1解析24 URLまで。同一解析内で成功・失敗をキャッシュし、保存済み本文も再利用する。既存の非空本文は過去の引用位置を保持するため更新せず、URL・タイトルだけの記録を更新対象にする。自動リダイレクトと認証情報の送信は行わず、HTML・テキスト以外は取得対象外。HTMLのscript等を除外して照合用テキストを保存し、取得不能時は既存の収集済み本文を維持する。アクセス制限や未対応の文字実体等による照合不能は残り得る。引用の一致だけで命題の意味的支持を承認することはない。

再評価中、保存した外部本文が既存の嗜好監査の`sources`経由で入力へ入る経路を検出したため、中断して修正した。通常版の嗜好監査、dark版の人物理解・嗜好監査では、[プロンプト用の出典変換](../worker/platform/provenance/sources.ts)で外部本文を空にし、ユーザー本文と出典識別子を保持する。サーバーの照合には元の本文を使う。20万文字の外部本文をDBへ保存した通常版・dark版の実際の監査メッセージを捕捉し、本文が流入せず、ユーザー引用が残ることを回帰テストで確認した。中断試行の使用量は最終15件の比較から分けて報告する。

## 本文復号・照応・自己類似の追加修正（2026-09-12）

default切り分け記録 `.artifacts/live-evaluation/20260912-user-a-default-diagnosis-01/diagnosis.md` をもとに、次の順で修正した。

1. [本文取得](../worker/platform/provenance/document.ts)の限定的な文字参照置換を、`entities@8.0.0`のHTML復号に置換した。HTMLRewriterで不要要素を除去してから本文を収集し、一度だけ復号する。曲がった引用符・その他の名前付き文字参照に対応し、二重エスケープや表示用タグ文字列を保持する。text/plainは復号しない。取得本文は検証用であり、LLMに送らない。既存の非空本文と引用位置は自動更新しない。
2. [照応の共通仕様](../worker/llm/prompts/reference-scope.ts)へ一本化した。明示主語を優先し、登録情報と前後文で一意な省略だけをinferredとして解決する。未指定の相手・行先を補わず、解釈の競合と単なる欠落を区別する。場面の性質を人物の心理へ移すことも禁止した。通常版・dark版の嗜好抽出／監査、通常版人物理解監査に各1回だけ組み込む。
3. 自己類似は人物側とユーザー側の特徴・経験の共通部分に限定し、候補の一部だけが支持される場合はラベル・条件を狭めて再判定する。低身長や失敗経験への自己照合を、工夫・努力・再挑戦への励ましと区別する。対象の範囲を先に決め、一致する場合だけ属性名を統一する。
4. プロンプト全体を再確認し、肯定的反応と対象が好きな理由の中で結び付く場合のpositive判定、inferredでも根拠集合が全体を支持できること、主体の整合性と事実の裏付け不足の分離を明確にした。反応経路だけ不明な場合の不要な質問指示も整理した。仮説・生成・修復の仕様には今回の問題に対応する追加変更は不要と判断した。

嗜好は`v3.11.0`、意味監査は`semantic-integrity/v1.7.0`、人物理解監査は`understanding-information/v1.7.0`。正本からプロンプト生成物とライセンス表示を再生成した。モデルとeffortはGPT-5.6 luna／デフォルトを維持する。

変更した全7登録プロンプトで、文字数・UTF-8バイト数は変更前以下、比較用`o200k_base`トークン数は減少した。通常版の抽出は6,574→6,428、監査は8,172→7,847、人物理解監査は2,835→2,813。スキーマ・ユーザーメッセージ・呼出上限は変更していない。提供先固有の使用量や、応答の変動による総入力削減を保証する値ではない。詳細は `.artifacts/analysis-scope-repair/budget.json`。

保存済みA15出力と出典のコピーを使うoffline replayでは、本文の復号だけで引用2件がinvalidからverified_quoteへ変わり、人物像の主張1件が不採用から採用へ変わった。もう1件は意味監査の条件で不採用のまま、誤字のある引用1件もinvalidのまま。既存DB・過去の評価成果物は更新していない。詳細は `.artifacts/analysis-scope-repair/entity-replay.json`。
