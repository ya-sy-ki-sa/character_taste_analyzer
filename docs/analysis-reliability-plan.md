# 解析の判定境界と補完処理の改修

## 目的と根拠

ユーザーAの登録比較と、同一モデルによる切り分け実験で確認した問題を改修する。先行実験では価値態度の過剰な追加が判定境界の明記で減ったが、対象と反復数は限定されている。人物理解の情報不足には、根拠検証後に補完を再判定しない処理順序が関係していた。反応経路の定義は抽出と監査で共有されていなかった。

先行記録はローカルの `.artifacts/live-evaluation/20260912-user-a-prompt-spec-01` と `.artifacts/live-evaluation/20260912-user-a-diagnosis-01/diagnosis.md` に保存している。今回の改修で上書きしない。

自己類似については、文脈的な自己照合を認める範囲を先に定義する。人物とユーザーの心理が客観的に一致するという認定とは分ける。Fake・Replayの成功を実LLMの意味理解の改善実証にはしない。

## 実装計画

1. 通常版の反応経路カタログを抽出・監査の共通system指示へ組み込む。外見評価・作劇評価・憧れ・行動への願望の境界を共通化し、dark版へ通常版の経路を混入させない。
2. 好みと規範的な価値態度を分離する。自己照合はユーザーの主観として根拠付け、反応の否定とユーザー経験の人物事実への転用を禁止する。監査は入力との照合で取りこぼしも点検する。
3. 人物理解の根拠検証・正規化を補完判定より先に実行する。正規化した人物像と不足理由を補完へ渡し、補完・再監査は各stageにつき1回まで。補完後も不足する場合は、不足表示と根拠のある候補を保持する。
4. 反応のみ不明なら監査内でresponseChannelをnullへ改訂し、改訂後の命題を再評価する。既存の引用・scope・根拠集合の採用条件を緩和しない。
5. 回帰テスト、型検査、生成物更新と`npm run verify`を実施する。既存登録の自動再解析・DB移行・モデル変更は含めない。

## 検証項目

- 抽出・監査に同じ定義が届くこと、dark版の処理境界が保たれること。
- 正規化前に十分でも正規化後に不足した人物像に補完が走ること。
- 補完で回復する場合、回復しない場合、既に十分な場合の呼出回数と保存結果。
- 補完後の実行記録・原出力ハッシュ、通常版カスタムの基本像／変更後の分離。
- 反応未確定の候補が保存・集計まで保持され、根拠のない候補は除外されること。

## 実装結果

2026-09-12に計画1〜4を実装した。[嗜好プロンプト](../worker/llm/prompts/preference.ts)は`v3.9.0`、[意味監査](../worker/llm/prompts/semantic-audit.ts)は`semantic-integrity/v1.5.0`、[人物理解](../worker/llm/prompts/understanding.ts)は`understanding-information/v1.6.0`へ更新した。反応定義は共通system指示に集約し、ユーザー側メッセージの重複した定義を削除した。

[人物理解の呼び出し処理](../worker/features/analysis/llm-understanding.ts)では、検証・正規化した候補から補完を判定する。判定用と保存用は[共通の出典準備](../worker/features/analysis/understanding-provenance.ts)と同じ検証・正規化関数を使用する。根拠検証中の失敗にも、完了済みの実行記録と再試行可否を引き継ぐ。原出力ハッシュは正規化前の応答に対する値を保持する。

判定前の出典読み取り・検証は増える。LLM呼び出しは各stageにつき通常2回、補完時4回の上限を維持するが、従来見逃していた不足が補完対象になるため、その登録では呼び出し数・待ち時間が増える。

## 検証結果と残作業

関連する6ファイル・67件のテスト、型検査、生成物の更新、変更文書6件のローカルリンク確認を通過した。引用不一致、scope不確定、補完の成功・未回復、十分な場合の追加呼び出しなし、原出力ハッシュ、失敗時の実行記録を検証した。

`npm run verify`は終了コード0で完了。単体・結合テスト702件（57ファイル）、E2E 32件、format・lint・型検査・契約・生成物・依存構造・ライセンス・ビルド・秘密情報走査・bundle予算を通過した。ログは `.artifacts/analysis-reliability/verify.log` に保存した。

lintの既存警告21件と、offline設定の`AI_GATEWAY_GATEWAY_ID`未定義等の既存警告は残る。WebKitはホストに`libgtk-4.so.1`がないため既存設定によって対象外で、未実行。E2Eの通過数に含めていない。

改修後の実LLM再評価は未実施。ユーザーAの同一入力・同一モデルでの登録比較と、[判定境界の対照例](preference-attribute-evaluation.md)による反復評価が残る。今回の固定応答テストから、価値態度・自己類似・願望の抽出精度やLLMの能力限界は結論しない。
