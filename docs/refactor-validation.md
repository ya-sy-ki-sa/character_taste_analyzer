# 現行機能を維持した再編の検証記録

基準コミットは `983c3d892dfedab751dd4ebcb7360797d42f7557`。着手時は変更のない作業ツリーで `npm run verify` が通過し、399件のテストと18件のE2E、代表画面32状態、ビルド容量、DB・属性・過去評価のハッシュを記録しました。

## 変更と不変条件

DB定義を `database/migrations` に移し、型付き通常版・dark版カタログからseedと語彙一覧を生成する構成にしました。53テーブルを含む116個のDDL定義、233件の属性のID・内容・所属ドメイン、2件の辞書バージョンは基準と一致しています。実行したDB適用はテスト・評価用の一時DBだけです。

6本のプロンプトの本文ハッシュとバージョンは基準と一致しています。過去評価JSON 10件もSHA-256が一致し、[履歴索引](../archive/README.md)に元の配置とハッシュを記録しました。

DataStoreStrategyと選択設定を除去し、HTTP・Workflowから機能別ユースケースを呼びます。Outboxの書き込みと配送を分け、実行入口で接続します。SQLを機能別リポジトリへ移し、既存の一括更新を保ったまま362個の固定バインド引数を名前付きタプルで検査できるようにしました。生成履歴は要求IDごとの集約に変更しました。

共有スキーマを分割し、OpenAPIを実際のルート登録から生成します。生成履歴URLを両APIプレフィックス配下の `generation-requests` へ統一し、JSON成功応答の旧形式読み替えを除去しました。dark版要約の入れ子データを文字列とする型の不一致も解消しました。分析器の集計バージョン表示は実装の定数から導出します。

登録画面の組み立ては約2,700行から173行、生成画面は194行となり、入力変換・送信・レビュー・候補比較・評価を対応する部品とフックへ分けました。CSSはレイヤー優先順位を保って役割別に分け、常に上書きされていた195宣言を除去しました。

## 検証結果

- `npm run verify`: ローカルで全ゲートを通過。35ファイル・416件の単体／結合テスト、26件のE2Eが成功。
- coverage対象: statements 96.67%、branches 90.49%。従来の閾値を維持。
- 現行DDLで重複配送、lease、途中失敗、再試行、古い世代、所有者・ドメイン分離、一括更新のロールバックを検証。
- 登録・理解／好みレビュー・再分析・集計・生成／採用・エクスポート・削除・認証をFake/Replayで検証。
- 実レスポンス検証、ルートとOpenAPIの一致、17生成資産の再現性、書き込みを伴わない差分検査を確認。
- 実行時の循環依存、実装からアーカイブ・評価・テストへの依存、機能から実行入口への逆参照はなし。SQLはリポジトリに集約。
- Fake評価67ケース: 分析エラー0、生成成功3、生成失敗0、根拠・選択項目不足による明示的な生成スキップ64。実モデル精度の合格判定には使用しない。

CIの実行定義も同じ `npm run verify` を使用します。GitHub上のCI起動・デプロイは今回の作業に含めていません。ローカルはChromium、Firefox、mobileで実行しました。WebKitはホスト依存ライブラリがないため、既存の環境判定に従って対象外です。CIではWebKit依存もインストールします。

CSS specificityの非致命的なlint警告は基準87件から22件へ減少しました。レイヤーをまたぐ既存の見た目を優先し、警告を消すための一律な並べ替えは行っていません。

## 画面比較

通常版・dark版それぞれ、1440×1000、1366×768、390×844、320×720でトップ・ログイン・空の登録一覧・空の生成画面を比較しました。
