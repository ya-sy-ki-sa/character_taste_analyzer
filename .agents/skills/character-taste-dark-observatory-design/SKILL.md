# Character Taste Dark Observatory Design

キャラ嗜好ラボのdark版を、単に背景が暗いUIではなく、**善の光が欠けるほど、抑えられていた影が満ちていく黒蝕式観測装置**として作る。清潔だった専用機が長い観測によって酸化・摩耗し、レンズの奥に説明できない軌道を捉え始めたような緊張を与える。

邪悪さは読みにくさ、流血、驚かせる演出では作らない。欠落、偏心、摩耗、冷たい余白、傷を暴く細い光によって作り、操作部分は明瞭に保つ。

## 共通基盤

このSkillは、同じプロジェクトのApache-2.0 Skill `character-taste-observatory-design` を基盤とする。作業前に、対象に応じて次を読む。

- 共通の製品世界観と実行フロー: `../character-taste-observatory-design/SKILL.md`
- 色、書体、筐体、観測スコープ: `../character-taste-observatory-design/references/visual-system.md`
- トップ／認証などの機能要件: `../character-taste-observatory-design/references/page-patterns.md`
- 実装、アクセシビリティ、ブラウザ検証: `../character-taste-observatory-design/references/implementation-verification.md`

dark版では本Skillの指定が通常版と異なる部分だけを上書きする。ユーザーが指定した機能と文言は、どちらの美術規則よりも優先する。

## 上書きの境界

dark版は通常版の別機能ではなく、同じ装置が黒蝕した状態である。

- 保持する: 情報構造、主要操作、認証項目、ラベルの意味、タイポグラフィの役割、筐体の主要領域、機能コンポーネント階層、アクセシビリティ、状態遷移。
- 上書きする: 共通の役割トークン値、スコープの幾何、表面の摩耗、局所光、補助的な物語文言。
- 追加しない: dark版だけの主要操作、偽の警告、偽の計測値、ユーザーを評価する状態。
- 実装では通常版と同じ`--ctl-*`役割トークンを差し替える。dark専用の腐食色や痕跡色だけを`--dark-*`補助トークンとして追加する。

## 核となる判断

1. **悪は足すものではなく、善が欠けた形で見せる。** 完全な円、均等な目盛り、清潔な金属、安心する光の一部を欠かせる。
2. **摩耗には原因を持たせる。** 指が触れる縁、熱を受けた遮光環、液体が溜まる下端だけを傷める。全面ノイズは禁止する。
3. **見慣れた装置を一か所だけ間違える。** 偏心した黒円、閉じない軌道、角度で形が変わる傷など、一つの説明不能な異常を主役にする。
4. **光は傷を暴く。** 発光は装飾ではなく、腐食、欠損、異常軌道、現在の操作を局所的に見せるために使う。
5. **闇の中でも操作は清潔に保つ。** 見出し、本文、入力、ボタン、フォーカス、エラーへ汚れやちらつきを重ねない。
6. **通常版の暖色と対照を作る。** dark版の主色は鈍色、酸化銀、青鋼、青黒とし、通常版の赤・黄の輝きを持ち込まない。主要文字は銀白、補助文字は明るい青灰にして暗部へ沈ませない。

## 汚染の上限

一つの画面で強い異常表現は最大3系統までにする。推奨は次の組み合わせ。

- 筐体の局所的な酸化または煤
- 偏心・欠損した日食スコープ
- 一本だけ規則を外れる異常軌道

VHSノイズ、グリッチ、血痕、触手、ルーン、点滅、霧を同時に重ねない。ジャンプスケア、ゴア、ユーザーの嗜好を「悪」と断定する文言も使わない。悪は装置に宿る視覚的比喩であり、ユーザーやキャラクターへの評価ではない。

## 実行フロー

1. 対象画面の機能と通常版の構造を確認し、保持する情報、操作、機能コンポーネント階層を決める。
2. 「何の光が欠け、何の影が満ちるか」を一文で決める。
3. 共通の役割トークンへdarkパレットを割り当て、摩耗箇所、一つの異常、局所光を定義する。
4. HTML/CSS/SVGで実装し、可読領域と汚染領域を分離する。
5. デスクトップとモバイルで、見た目に加えて認証操作、フォーカス、モーション軽減を確認する。
6. ただ高級な黒金UI、ネオンUI、ホラーゲーム画面に見える要素を削り、キャラ嗜好ラボ固有の観測軸を残す。
