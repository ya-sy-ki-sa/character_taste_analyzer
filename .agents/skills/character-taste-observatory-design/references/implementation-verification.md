# 実装と検証

## 1. 実装前

1. `package.json`、ルート、既存コンポーネント、テーマ、lint／format／testコマンドを確認する。
2. 対象画面の実データ、状態、操作、エラー、空状態を列挙する。
3. 既存のユーザー変更を保持し、無関係なファイルを変更しない。
4. 色、書体、余白、境界、モーションをトークン化し、一回限りの値の乱立を避ける。
5. 通常版とdark版の両方が対象なら、同じ情報構造とコンポーネントが共通の役割トークンだけで切り替わるか確認する。

## 2. 実装基準

- 既存フレームワークとコンポーネント規約を使う。静的モックならHTML/CSS/JavaScriptでよい。
- UIの文字、ボタン、入力、表、グラフはコードネイティブにする。スコープと目盛りはCSSまたはSVGを優先する。
- 反復要素は共通コンポーネントまたは共通クラスにし、差は名前のあるvariantで表す。
- 主要操作、タブ、フィルター、モーダル、選択は、モックでも見える状態変化を実装する。
- アニメーションはtransformとopacityを優先し、レイアウトシフトを起こさない。
- 追加依存は、既存機能で代替できず効果が明確な場合に限る。
- 実データがない画面で、もっともらしい指標や分析結果を捏造しない。モックデータならコードと表示の両方で明確にする。

## 3. アクセシビリティ

- `header`、`main`、`nav`、`section`、`aside`、`footer` と正しい見出し階層を使う。
- 図としてのスコープには、観測軸と意味が分かる代替説明を付ける。装飾SVGは支援技術から隠す。
- 全操作をキーボードで到達・実行可能にし、`focus-visible` を明瞭にする。
- モーダルは可能ならネイティブ`dialog`または実績ある既存部品を使い、フォーカストラップ、Escape、復帰フォーカスを確認する。
- `prefers-reduced-motion: reduce` で走査、点滅、視差移動を停止し、状態は静止画でも理解できるようにする。
- 色だけで状態や系列を区別しない。文言、形、線種、記号を併用する。
- 日本語の本文、フォームラベル、保護情報は原則14px以上にする。装置IDや角度などの補助情報だけを10–12px相当にできる。ズーム200%でも主要操作と内容が欠落しないようにする。

## 4. ブラウザ検証

ビルド成功だけで視覚的な完了を主張しない。ローカルサーバーまたは静的ファイルをブラウザで開き、最低でもデスクトップとモバイルを確認する。トップ／認証画面では次の4サイズを推奨する。

- 1440 × 1000: 標準デスクトップ
- 1366 × 768: 高さの低いラップトップ
- 390 × 844: 標準的なモバイル
- 320 × 720: 最小幅

### 必須の視覚チェック

1. 最初のビューポートで主見出しと主要操作が読め、意図せず切れていない。
2. テーマの主要文字と補助文字が暗い背景で十分に読める。通常版は生成り、dark版は銀白と明るい青灰を確認する。
3. 筐体、操作盤、スコープ、校正部の比率に主従があり、枠が密集していない。
4. 日本語の禁則、折返し、行長が自然で、英字ラベルが主役になっていない。
5. 320px幅で横方向のオーバーフローがない。
6. Primary、Secondary、選択、非活性、エラーの状態が区別できる。
7. 目的のないカード、ピル、バッジ、グロー、偽の数値が混入していない。
8. 両テーマを扱う場合、通常版は完全な幾何と赤黄の局所光、dark版は欠損した幾何と鈍銀・青鋼の局所光として判別でき、機能差は生じていない。

### 必須の操作チェック

- トップ画面: 新規ユーザ作成とログインがそれぞれ正しい画面またはモーダルを開く。
- 認証: ラベル、autocomplete、パスワード種別、必須検証、送信、閉じる、Escape、背景クリックの仕様を確認する。
- 分析: 条件変更、開始、処理中、結果、失敗、再試行のうち実装対象の経路を通す。
- 履歴: 行選択、ソート、フィルター、ページ移動など表示された操作を試す。
- 共通: Tab順序、フォーカス表示、Hover／Active、モーション軽減を確認する。

コンソールエラー、読込失敗、水平オーバーフローがあれば修正して再確認する。スクリーンショットが利用できる場合は各代表幅を撮り、実際に目で比較する。

## 5. 完了時の報告

次を簡潔に報告する。

- 変更したファイル
- 採用した装置表現と、画面の主役
- 実行したlint、test、buildと結果
- 確認したビューポート
- 実際に通した主要操作
- 意図的に残した制約または未実装事項
