# Character Taste Observatory Design — Normal / Shared Base

キャラ嗜好ラボの通常版を、宇宙風の装飾を載せたWebサイトではなく、**人が惹かれるキャラクターの傾向を測定・記録・比較する、整備された専用観測装置**として設計する。画面を見た人が一目で同じ製品だと認識でき、暗い観測室でも情報と操作が明瞭であることを目標にする。

ここでいう「通常版」はブラウザのlight themeを意味しない。暗室向けの低明度な筐体に、磨かれた真鍮、生成り、赤い信号、黄白の局所光を配した**正常稼働状態**を指す。黒蝕した物語上のdark版とは、色、表面、幾何の状態で区別する。

## 通常版とdark版の契約

両テーマは別製品にしない。情報構造、機能、文言の明快さ、タイポグラフィの役割、ヘッダー／操作盤／スコープ／フッターという筐体の主要領域、アクセシビリティは共有し、美術状態だけを対照化する。校正レールや故障表示のような補助部品は、テーマの物語に応じて置換・省略できる。

| 観点 | 通常版 | dark版 |
|---|---|---|
| 装置状態 | 整備済み、正常稼働 | 酸化・摩耗し、黒蝕を観測 |
| 主幾何 | 完全な円、閉じた星図、均等な目盛り | 偏心、欠損、閉じない異常軌道 |
| 構造色 | 磨かれた真鍮、生成り | 鈍色、酸化銀、青鋼、銀白 |
| 信号光 | 赤と黄白の安定した局所光 | 冷たい青と銀の抑制した局所光 |
| 表面 | 清潔で軽い使用感 | 原因のある局所的な煤、傷、酸化 |

- 通常版またはテーマ指定なしの依頼では、本Skillを通常版として使う。
- 日食、黒蝕、悪、闇、侵食、不穏なdark版の依頼では、兄弟Skill [character-taste-dark-observatory-design](../character-taste-dark-observatory-design/SKILL.md) を併用し、その固有規約を優先する。
- テーマ切替で機能、主要操作、認証項目、状態の意味を変えない。色だけに頼らず、同じラベル、形、線種、状態文言を保つ。

## 適用時の前提

- ユーザーが指定した機能、文言、情報構造を優先する。世界観を理由に機能を追加・削除しない。
- 既存スタック、コンポーネント、ルーティング、状態管理、テスト方法を先に確認し、それらへ適合させる。
- `mock-top-01-constellation.html` が存在すれば現行の視覚サンプルとして確認してよい。ただし、このSkill内の規約だけで実装できる状態を維持し、モックへの依存は作らない。
- 画面の主目的を一文で定義し、その目的に必要な装置だけを置く。意味のない計器、数値、ステータス、装飾ラベルは作らない。

## 必ず読むリファレンス

作業内容に応じて次を読む。大規模な画面改修では3ファイルすべてを読む。

- 色、書体、質感、レイアウト、象徴的な観測スコープを扱う場合は [visual-system.md](references/visual-system.md) を読む。
- トップ／認証、分析、履歴、設定、文言、コンポーネントを扱う場合は [page-patterns.md](references/page-patterns.md) を読む。
- 実装、レスポンシブ、アクセシビリティ、ブラウザ検証を行う場合は [implementation-verification.md](references/implementation-verification.md) を読む。

## デザインの核

1. **主役は観測スコープ。** 円形レンズ、照準、星図、観測軸など、その画面の目的を表す一つの装置を記憶に残る要素にする。
2. **画面全体は一台の筐体。** カードを並べず、外枠、仕切り線、操作盤、レール、目盛りで情報を構成する。
3. **暗さより判読性を優先。** 黒に近い背景へ高明度の本文を置き、低コントラストの極小文字で雰囲気を作らない。通常版は生成り、dark版は銀白を使う。
4. **意味のある機械語彙を使う。** 観測、焦点、座標、記録、解析などを機能と対応させる。通常のユーザーが理解できない比喩には、平易な日本語を併記する。
5. **大胆さは一か所へ集める。** 巨大なスコープや非対称な操作盤を主役にし、周囲は静かな線、余白、タイポグラフィで支える。

## 実行フロー

1. 対象画面のユーザー、主目的、主要操作、必須状態、既存制約を確認する。
2. その画面で「何を観測・調整・記録するのか」を決め、情報構造と装置の形を対応させる。
3. 通常版かdark版かを確定し、リファレンスに従ってトークン、タイポグラフィ、グリッド、主要コンポーネント、モーションを定義する。
4. 実際に操作できる画面を既存スタックで実装する。テキスト、フォーム、グラフ、照準、目盛りは可能な限りHTML/CSS/SVGで作る。
5. デスクトップとモバイルをブラウザで確認し、主要操作、フォーカス、長い日本語、モーション軽減、横方向のはみ出しを検証する。
6. 汎用的なAI生成UIへ戻っていないか自己批評し、目的のない装飾を一つ以上取り除いてから完了する。

## 禁止する既定解

- 紫〜青のグラデーション、ネオン・サイバーパンク、過剰な発光
- ガラス風カードの反復、角丸カードの3列配置、中央寄せ見出し＋3機能
- 意味のない `01 / 02 / 03`、偽の指標、バッジ、ロゴ群、眉見出し
- すべてをピル型にすること、強すぎるドロップシャドウ、ストック風宇宙画像
- 背景に星を散らすだけの「宇宙テーマ」や、読みづらい装飾用の英字
- 見た目だけで動かないタブ、ボタン、フィルター、フォーム
