# DD-16 現行実装トレーサビリティ

## 1. 現行機能と契約

| 機能 | API | 主なD1 | 回帰検査 |
|---|---|---|---|
| 登録・認証 | `/users`, `/sessions`, `/me` | `users`, `credentials`, `sessions` | auth unit、E2E login |
| Entry 3 variant | `/entries`, `/identity-candidates` | `user_character_entries`, `entry_revisions`, `sources`, `source_sets` | Zod/OpenAPI、E2E registration |
| 基本像review | `/understanding-snapshots/{id}/review` | understanding、review、evidence | review branch unit／E2E |
| 嗜好review | `/preference-analysis-runs/{id}/review` | analysis、preference、value stance | review branch unit／E2E |
| Profile／Graph | `/profile`, `/profile/graph` | projection、snapshot、graph | aggregation／freshness test |
| 生成 | `/generation-requests`, `/generated-characters` | generation request／brief／character／basis／validation | generation／validator／E2E |
| Export | `/account/exports` | `account_exports`, jobs | export schema 3.0／E2E |
| Account削除 | `DELETE /account` | user所有table、R2 export | ownership／deletion test |

## 2. OCP境界

次のpolymorphic boundaryは互換機能ではなく、拡張に対して閉じた安定Portとして維持する。

- `CharacterTasteDataStoreStrategy`、Factory、D1 Adapter
- LLM Provider実装、Factory、Fallback router
- Embedding Provider実装、Factory
- Entry登録種別、review操作等の実在variantを表す判別共用体

未知のStrategy／Provider設定はfail-fastとする。D1 SQLはD1 Adapter内部に閉じ込める。

## 3. 削除契約

次が再導入されないことを契約testで固定する。

- Entry v1 field／schemaと旧fallback
- key rotation endpointとcredential/session generation
- `legacy_unverified`
- Profile `patterns`
- generated character revision ID
- 予約table、固定列、統合前table
- `DEPLOYMENT_PROFILE`、Vectorize binding／readiness

## 4. Release gate

```bash
npm run typecheck
npm test
npm run contracts
npm run build
npx playwright test --project=chromium
```

DDLは空DBへ適用し、53テーブル、FK、index、ontology seedを検証する。OpenAPIはWorker routeとZod schemaから生成し、手書きの別契約は置かない。
