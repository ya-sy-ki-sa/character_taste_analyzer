# DD-12 嗜好グラフ詳細設計

## 1. 採用構成

初期構成の`BrowserGraphEngine`は抽象名ではなく、次の組合せとする。

- Graphology: browser内のgraph data structure、属性、探索algorithm
- Graphology standard library: connected component、shortest path等
- ForceAtlas2 Web Worker: layout計算
- Sigma.js: WebGL描画、pan/zoom、node/edge interaction
- 専用Web Worker: GraphProjection読込、検証、graph構築、filter、探索、layout制御
- IndexedDB: projection cache。正本ではない

ブラウザ内に永続graph DBを置く設計ではない。D1から作ったユーザー単位GraphProjectionを、browser memory上のGraphologyへ読み込んで処理する。

## 2. 責務境界

| Server | Browser Worker | UI main thread |
|---|---|---|
| owner認可 | schema検証 | Sigma描画 |
| assertion/profile集計 | Graphology graph構築 | panel・tooltip |
| projection世代・node/edge生成 | filter・neighbor・path | keyboard操作 |
| evidence参照制御 | layout、表示用metric | selection状態 |
| page/cursor配布 | IndexedDB cache | URL query同期 |

browserは新しい嗜好scoreを確定しない。centrality等の探索値は表示用一時値であり、ProfileProjectionへ書き戻さない。

## 3. GraphProjection

正式JSON契約は[GraphProjection Schema](schemas/graph-projection.schema.json)とする。

### 3.1 Node

| type | ID形式 | 例 |
|---|---|---|
| user | `u:self` | 本人。owner UUIDはpayloadへ出さない |
| work | `w:{workId}` | 作品 |
| character_identity | `ci:{identityId}` | キャラクター本体 |
| representation | `cr:{representationId}` | facet/scene/custom等 |
| attribute | `a:{stableKey}` | 統制属性 |
| raw_attribute | `ra:{sha256(normalizedLabel)[:24]}` | 自由語 |
| response_channel | `rc:{channel}` | 反応経路 |
| value_stance | `vs:{orientation}:{stance}:{targetHash}` | 価値スタンス |
| context | `ctx:{conditionHash[:24]}` | 条件 |
| profile_pattern | `pp:{patternId}` | 複合pattern |

Node IDは同一projection内で一意。character等のprivate resource UUIDをnode IDへ含めてもresponse自体が認証済みprivate dataなのでよいが、owner user UUIDは含めず、node IDをlogやanalyticsへ送らない。

### 3.2 Edge

| type | source → target | 意味 |
|---|---|---|
| likes/dislikes | user → attribute/raw attribute | 嗜好方向。別edgeで保持 |
| has_attribute | representation → attribute | 基本像の属性 |
| in_work | identity → work | 作品所属 |
| represented_as | identity → representation | 表現 |
| responds_via | preference/attribute相当 → response channel | 反応経路 |
| has_stance | user → value stance | 価値スタンス |
| conditioned_by | likes/dislikes/stance相当 → context | 条件 |
| supports_pattern | node → profile pattern | pattern構成 |
| related_attribute | attribute ↔ attribute | ontology relation |
| derived_from | representation → representation | base/custom関係 |

Graphologyはmulti directed graphを使う。同じnode間のlikes/dislikesやchannel違いを別edgeで保持する。

## 4. Projection mapper

入力は一つのcurrent ProfileProjection、active entry、関連Character/Work、confirmed understandingである。

1. user nodeを一つ作る。
2. 表示対象dimensionごとにattribute/raw nodeを作る。
3. positiveScore > 0ならlikes、negativeScore > 0ならdislikesを別edgeで作る。
4. response channel・contextがある場合はnodeとedgeを追加する。
5. dimension evidenceに含まれるidentity、representation、workを追加する。
6. confirmed value stanceと表示対象patternを追加する。
7. ontology relationは表示中attribute同士だけ追加する。
8. node/edgeをID昇順にcanonicalizeしcontent hashを計算する。

edge weightはProfile scoreまたはunderstanding confidenceであり、道徳的善悪を係数にしない。

## 5. Detail level・上限

| detail | 全体node/edge上限 | 内容 |
|---|---:|---|
| summary | 300 / 1,200 | stable/emerging上位、主要character、value stance |
| standard | 1,000 / 5,000 | 通常表示、条件・channel・patternを含む |
| expanded | 3,000 / 15,000 | evidence関連representationまで。page分割 |

1 response pageは最大node 1,000、edge 5,000。edgeが参照するnodeは同じpageに含めるか、既に前pageで配布済みでなければならない。

上限超過時は次の順に省略する。

1. `insufficient`かつscore 0.20未満
2. weightの低いontology relation
3. 表示対象外dimensionのevidence representation
4. confidenceの低いpattern

悪、ヴィラン、端役というcategory自体を省略優先条件にしない。

## 6. API load

```text
GET /api/v1/profile/graph?detail=standard&limit=500
GET /api/v1/profile/graph?detail=standard&limit=500&cursor=...
GET /api/v1/profile/graph/nodes/{nodeId}/neighbors?profileSnapshotId=...&depth=1
```

各pageは同じ`projectionId`、`contentHash`を返す。途中で世代が変わった場合は409 `PROJECTION_CHANGED`を返し、clientは先頭から読み直す。ETagは`"graph-{contentHash}-{pageHash}"`。

API envelopeの`meta.page`に`nextCursor/hasMore`、`data`にGraphProjection pageを入れる。

## 7. Worker protocol

Main threadとWorkerはdiscriminated union messageを使う。requestごとに`requestId`を付け、古いresponseを破棄できるようにする。

```typescript
type GraphWorkerCommand =
  | { type: "INIT"; requestId: string; projection: GraphProjectionPage }
  | { type: "APPEND_PAGE"; requestId: string; projection: GraphProjectionPage }
  | { type: "SET_FILTER"; requestId: string; filter: GraphFilter }
  | { type: "NEIGHBORS"; requestId: string; nodeId: string; depth: 1 | 2 }
  | { type: "SHORTEST_PATH"; requestId: string; source: string; target: string }
  | { type: "START_LAYOUT"; requestId: string; settings: LayoutSettings }
  | { type: "STOP_LAYOUT"; requestId: string }
  | { type: "DISPOSE"; requestId: string };

type GraphWorkerEvent =
  | { type: "READY"; requestId: string; stats: GraphStats }
  | { type: "PATCH"; requestId: string; visibleNodes: string[]; visibleEdges: string[] }
  | { type: "NEIGHBORS_RESULT"; requestId: string; nodeIds: string[]; edgeIds: string[] }
  | { type: "PATH_RESULT"; requestId: string; nodeIds: string[]; edgeIds: string[] }
  | { type: "LAYOUT_TICK"; requestId: string; positions: Float32Array }
  | { type: "ERROR"; requestId: string; code: string; message: string };
```

大きなposition配列はTransferableで渡す。main threadへGraphology instanceを渡さない。

## 8. Graphology構築

```typescript
const graph = new MultiDirectedGraph({ allowSelfLoops: false });
for (const node of nodes) graph.mergeNode(node.id, node);
for (const edge of edges) {
  assert(graph.hasNode(edge.source) && graph.hasNode(edge.target));
  graph.mergeDirectedEdgeWithKey(edge.id, edge.source, edge.target, edge);
}
```

同じedge IDでpayloadが異なるpageは`GRAPH_INCONSISTENT_PAGE`として全cacheを破棄する。dangling edge、self loop、NaN/Infinity、範囲外weightをschema後のsemantic validationで拒否する。

## 9. Layout

初期layout:

1. deterministic seedでcircular初期配置
2. ForceAtlas2 Web Worker、Barnes-Hut有効
3. 300 node以下は2秒、1,000 node以下は5秒を目安に停止
4. user nodeと選択nodeを固定可能
5. UI操作中は描画を優先し、layout tickを最大10fpsに間引く

既定setting:

```typescript
const layout = {
  barnesHutOptimize: true,
  barnesHutTheta: 0.6,
  gravity: 1,
  scalingRatio: 8,
  strongGravityMode: false,
  slowDown: 2,
  edgeWeightInfluence: 0.5
};
```

expandedで1,000 nodeを超える場合は全体ForceAtlas2を自動開始せず、community/neighbor単位の表示を促す。

## 10. Filter・探索

```typescript
interface GraphFilter {
  nodeTypes: string[];
  polarity: Array<"positive" | "negative">;
  responseChannels: string[];
  classifications: Array<"stable" | "emerging" | "insufficient">;
  minWeight: number;
  minConfidence: number;
  includeConditional: boolean;
  textQuery?: string;
}
```

- neighbor depthはclient 2まで、server neighbor APIも2まで
- shortest pathはvisible graph内、unweighted BFSを既定とする
- weighted pathが必要な場合のcostは`1 / max(weight × confidence, 0.01)`
- degree/centralityは「重要度」ではなく「このprojection内の接続数」と表示する
- graphから医学的・人格的推論を生成しない

## 11. 描画規則

- node色はcategory/typeを表す。善=明色、悪=暗色等の価値序列にしない
- likesは実線、dislikesは破線、mixedは両edgeまたは二色線
- node sizeは`6 + 18 × sqrt(weight)`、上限24px
- confidence低は透明度を下げ、悪属性だから透明度を下げない
- shape/colorだけに依存せずlabel、凡例、patternも併用する
- edge tooltipにscore、confidence、条件、根拠件数を表示する

## 12. UI interaction

- click: node選択、右panel表示
- double click/Enter: neighbor展開
- Escape: 選択解除
- arrow/tab: keyboard node移動
- search: labelの部分一致で候補list、選択時にcamera移動
- 「このつながりの根拠」: server evidence APIへ遷移
- graphが利用できない場合: 同じ内容のtable/list viewを提供

## 13. Cache・privacy

IndexedDB key:

```text
graph:{userId}:{projectionId}:{detail}:{contentHash}
```

- valueはvalidated projection pageと取得時刻
- currentと直前projectionだけ保持
- logout、account deletion完了で削除
- shared computer対策として「この端末に保存しない」を設定可能
- analyticsへnode label、character名、attribute、graph structureを送らない

## 14. 性能受入値

中位class desktop/mobile browserを対象に測る。

| 条件 | 目標 |
|---|---:|
| standard 1,000 node/5,000 edge parse+build | 2秒以内 |
| filter反映 | 200ms以内 |
| depth 1 neighbor | 100ms以内 |
| main thread long task | 50ms超を連続発生させない |
| layout中のUI | 30fps以上を目標 |

達成できない端末ではsummaryへ自動縮退し、list viewを維持する。

## 15. 将来Graph DB

全ユーザー横断探索、server-side multi-hop、recommendation、共有catalog graphが要件化した時点で`GraphProjectionRepository`/`GraphQueryStrategy`のserver Adapterを追加する。現在のGraphProjection schemaは配布形式として維持できる。

専用graph DBへ移行しても、ユーザーの嗜好正本・訂正履歴はRDBに残す。Graph DBはprojection/query storeとし、削除・再構築可能性を維持する。
